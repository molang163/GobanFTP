## Feedback Summary

Paul said he could get the general idea of GobanFTP, and that the detailed
README with images was a step in the right direction. The main improvement he
suggested was to make the README clearer for newcomers before the protocol
details start.

The most important questions to answer earlier:

- What is GobanFTP's core purpose?
- Is it mainly for playing Go this way, demonstrating the protocol concept, or
  something else?
- When is the project a good candidate for a reader?
- Can a demo or specimen appear before the longer setup instructions?

For GobanFTP, the working answer is:

> GobanFTP is primarily a protocol experiment and proof object. The playable
> terminal mode is a demo surface. The core idea is replay truth from public,
> enumerable event filenames.

## README Patterns To Learn

Paul's reference README is useful because it gives newcomers a staged entrance:

- It says what the project is before explaining internals.
- It shows a demo before long instructions.
- It includes a "What Sets It Apart" style section.
- It includes a "When is it a good candidate?" style section.
- It separates audience fit from installation details.

## GobanFTP Follow-Up Ideas

These are editorial ideas for future README polish, not protocol requirements:

- Add a short "What This Is For" section near the top.
- Add a short "Not For" section near the top.
- Put the static witness specimen or demo link before the longer proof gate.
- Explain that terminal play is a demo surface, not the main product purpose.
- Keep the weird protocol-art tone, but let the first-time reader stand on plain
  language before the ritual vocabulary appears.
